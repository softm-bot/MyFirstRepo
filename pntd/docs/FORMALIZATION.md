# Формализация домена ПНТД

Версия артефакта: **0.2** (2026-09-27).  
Основание: публичные поверхности pntd.ru и анонимно доступные ресурсы gost.info/pntd (gate 401 + `/assets/app.js|css`); снимок схемы gost-documents (`documents`, `organizations`, метки `НД-*`).  
Закрытый HTML прототипа после авторизации **не исследовался** (форум progost/forum2 недоступен гостю).

---

## 1. Цель формализации

Зафиксировать устойчивую модель:

1. **Открытого указателя НТД** (pntd.ru) — карточки, классификаторы, статусы, связи, поиск.
2. **Закрытой продуктовой линейки PNTD** (gost.info/pntd) — допуск, каталог, тарифы, комплекты, темы UI.
3. **Границ** с внутренним реестром gost-documents и метками `НД-*` в КП.

Модель нужна как контракт для дальнейшей реализации/миграции данных, а не как чат-резюме.

## 3. Плоскость A — открытый указатель

### 3.1. Назначение (с главной pntd.ru)

Информационная система учёта и представления НТД: межгосударственные и национальные стандарты, своды правил, технические условия, классификаторы и методические документы. Аудитория: инженеры, нормоконтроль, метрология, закупки, стандартизация.

Публичная часть: карточки, поиск, классификаторы, перекрёстные ссылки. Управление базами, версиями и оргпроцессами заявлено как предмет развития платформы.

Объём (meta, 2026-09): **62 999+** карточек.

### 3.2. Сущность DocumentCard

Идентификатор в URL: целочисленный `id` → `/nd/{id}.html`.

| Поле (UI) | Смысл | Пример |
|-----------|--------|--------|
| Обозначение | Канонический код НТД | `ГОСТ 24297-87` |
| Заглавие (RU / EN) | Наименование | Входной контроль продукции… |
| Статус | Действует / Заменен / … | `Заменен` |
| Дата введения | Вступление в силу | `01.01.1988` |
| Дата огр. срока действия | Ограничение срока | `01.01.2014` |
| Вид стандарта | Класс вида (число + текст) | `4 - Стандарты на методы контроля` |
| Вид требований | Сертификация / отметки | `Документ имеет отметку *` |
| Организация-разработчик | Разработчик | Госкомитет СССР по стандартам |
| Документ внесён организацией СНГ | Вносящая сторона | … |
| Разработчик МНД | Страна/сторона МНД | Российская Федерация |
| Управление Ростехрегулирования | Код + название управления | `530 - …` |
| Межгосударственный ТК / номер ТК | Технический комитет | `274` |
| Приказ о закреплении за ТК | номер + дата | `147` / `26.01.2023` |
| Дата последнего издания | Переиздание | `01.05.2009` |
| Номер(а) изменении(й) | История изменений | `переиздание` / `с изм. 1` |
| Количество страниц | Объём оригинала | `8` |
| Аннотация | Область применения | … |
| Ключевые слова | Теги | … |
| Термины и определения | Ссылка на приложение и т.п. | `Приложение` |

Вкладки карточки (DOM): **основные атрибуты**, **область применения**, **классификаторы**, **связанные**.

### 3.3. Статусы

Наблюдаемые CSS-классы на pntd.ru:

| Класс | Типичный текст / буква в выдаче | Смысл |
|-------|----------------------------------|--------|
| `is-active` | Действует · `Д` | Действующий |
| `is-replaced` | Заменен · `З` | Заменён другим документом |
| `is-cancelled` | (Утратил силу / отменён) · `У` | Снят с действия |
| `is-adopted` | Принят | Принят, ещё не/особый режим введения |
| `is-unknown` | `?` | Статус не определён в указателе |

Буквы `Д` / `З` / `У` / `?` используются в поиске и в таблицах связей как компактный маркер статуса **связанной** карточки.

### 3.4. Виды обозначений (справка на главной)

| Префикс/вид | Описание |
|-------------|----------|
| ГОСТ | Межгосударственный стандарт |
| ГОСТ Р | Национальный стандарт РФ |
| СП | Свод правил (отдельные карточки с годом редакции) |
| ТУ и прочие | Технические условия и иные НТД в корпусе указателя |

Также встречаются составные обозначения (ГОСТ ИСО…, ГОСТ Р ЕН…, ГОСТ IEC…, ГОСТ Р ИСО/ТС…).

### 3.5. Классификаторы

Каждая карточка может нести пути сразу в четырёх системах:

| Система | Маршрут UI | Форма кодов (наблюдение) |
|---------|------------|---------------------------|
| ОКС | `/ok/oks.php`, `/ok/{code}_oks.php` | `03` → `03.120` → `03.120.10` |
| КГС | `/ok/kgs.php`, `/ok/kgs/{А}.php` | Раздел `Т` → `Т5` → `Т51` |
| ОКСТУ | `/ok/okstu.php`, `/ok/okstu/{code}.php` | Часто `0000`, `0025` (не путать с ОКС) |
| ГРНТИ | `/grnti.php`, `/grnti/{nn}.php` | `81` → `81.81` → `81.81.05` |

На карточке классификатор показан деревом (`doc-class-tree`) с текущим узлом (`is-current`).

### 3.6. Связи между документами

Типы, видимые в UI карточки:

| Тип связи | Смысл |
|-----------|--------|
| `replaces` / заменяемые | Документы, которые данная редакция заменяет |
| `replaced_by` / заменяющий | Документ, которым заменён текущий |
| `normative_ref_gost` | Нормативные ссылки на ГОСТ |
| `normative_ref_other` | Нормативные ссылки на прочие НД |
| `cited_by` | Документы, ссылающиеся на текущий |

Связь всегда указывает на другую `DocumentCard` (через `/nd/{id}.html`) и может нести маркер статуса цели.

### 3.7. Поиск

- Endpoint: `GET /search.php?q=…`
- Выдача: таблица (маркер статуса, обозначение, название) → карточка.
- Запрос принимает обозначение, ключевое слово, тему.

### 3.8. Use-cases (указатель)

1. Найти документ по обозначению и проверить статус.
2. Открыть карточку и прочитать область применения / ключевые слова.
3. Перейти по классификатору (ОКС/КГС/ОКСТУ/ГРНТИ) к соседним документам.
4. Пройти цепочку «заменён → заменяющий» и нормативные ссылки.
5. Использовать указатель как вход в предметную область без покупки полного текста/базы.

## 4. Плоскость B — закрытая линейка gost.info/pntd

### 4.1. Доступ (AccessGate)

| Атрибут | Значение (публичный gate) |
|---------|---------------------------|
| HTTP для гостя | **401** |
| Title | «Допуск — PNTD» |
| Обозначение | `PNTD-GATE` |

### 4.2. Темы оформления

Переключатель `data-themes` / cookie `pntd_theme` / query `?theme=`.  
Наблюдаемые id: `reglament`, `kontur`, `garant`, `wiki`, `dzen`, `regru`, `rostsayt`, `superjet`, `hartmans`, `lada`, `lemme`, `cocos`, `tefi`, `endigo`, `daiks`, `beauty`, `gost`, `blueprint`, `vault`, `terminal`, `archive`, `industrial`, `signal`, `graphite`, `nord`, `ink`, `sand`, `copper`, `ocean`, `forest`, `chronicle`, `lattice`, `metro`, `nalog`, `slab`, `ivory`.

Темы — презентационный слой, не доменные сущности НТД.

### 4.3. Сущности каталога и комплектов (из app.js)

Вывод по публичному `/pntd/assets/app.js` (логика UI после gate):

| Сущность | Признаки в DOM/JS | Описание |
|----------|-------------------|----------|
| **CatalogItem** | `software_code[]`, `base_article[]`, `.catalog-article`, `.cell-sku` | Позиция прайс-листа |
| **kind** | `data-kind`: `software` \| `base` | Тип позиции |
| **Price** | `.price-input`, натуральное число ≥ 1; пусто = нет цены | Редактирование с dirty/save |
| **Base tariffs** | `data-tariffs` JSON, select `[data-kit-base-range]`, ключ по умолчанию `price_local` | Несколько цен на базу |
| **Bases catalog form** | `data-bases-form`, `bases[i]…`, add/remove row | CRUD строк баз |
| **CopyForm** | `form.copy-form`, `.copy-input` | Редактирование текстовых полей карточек линейки |
| **Kit / Case** | `[data-kit]`, `data-kit-id`, `case[id][code|kind|tariff|qty][]` | Комплект позиций |
| **Subscription months** | `[data-kit-months]`, min≈4 max≈100 | Срок в месяцах |
| **Discount** | `data-discount` (по умолчанию 40), если months ≥ 12 | Скидка как при годовом продлении |
| **Open price** | пустой `data-price` → «по запросу» | Не входит в сумму |

Инварианты цен (клиентская валидация):

- цена — натуральное число (`^[1-9]\d*$`), без нуля/дробей/текста;
- сохранить можно только dirty + валидные поля;
- qty комплекта: 1…9999.

### 4.4. Use-cases (линейка)

1. Получить допуск через форум и открыть контур `/pntd/`.
2. Вести каталог ПО и баз (артикулы, SKU, цены, тарифы баз).
3. Собрать комплект (case): позиции × количество × срок, увидеть сумму и скидку ≥12 мес.
4. Править сопроводительные тексты (copy-form).
5. Переключать тему UI под демо/бренд-контакт.

## 7. Инварианты и открытые вопросы

**Инварианты**

1. `DocumentCard.id` стабилен в URL; обозначение может меняться между редакциями → связь `replaced_by`.
2. Классификаторные привязки множественные и многоуровневые (путь, не один лист).
3. Линейка PNTD оперирует SKU/тарифами, а не id карточек pntd.ru (явного моста в публичном JS нет).
4. Гость не видит HTML контура; статика assets не является секретом домена.

**Открыто (нужен владелец / сессия)**

- Полный перечень сущностей экранов за gate (разделы меню, сущности «регламент», хранение цен).
- Есть ли связь CatalogItem ↔ DocumentCard (обозначение НТД в SKU).
- Серверная модель прав (роли beyond «допуск есть/нет»).
- Источник данных pntd.ru (БД, импорт из NormaCS и т.д.) — не публичен.

## 9. Жизненный цикл

### 9.1. Карточка НТД (плоскость A)

```
draft/import → published (active|adopted|unknown)
                 │
                 ├─→ replaced  (появляется связь replaces / replaced_by)
                 ├─→ cancelled (маркер У; ограниченный_until / снятие с действия)
                 └─→ republish / amendment (last_edition_date, amendment_notes; id URL стабилен)
```

Правила:

1. Публикация на pntd.ru делает карточку доступной поиску и классификаторам.
2. Смена статуса **не** меняет `id` в `/nd/{id}.html`.
3. Новая редакция с новым обозначением → отдельная карточка + связь `replaces`/`replaced_by`.
4. Классификаторные привязки обновляются независимо от статуса (путь кодов может расширяться).

### 9.2. Позиция линейки / комплект (плоскость B)

```
CatalogItem: created → priced | open_price → (optional) linked_to_ntd_designation → archived
Kit/Case:    assembled → priced_sum (± discount ≥12 мес.) → quoted / copied → discarded
Gate:        closed_no_access → access_granted (сессия форума) → expiry/revoke (не публично)
```

### 9.3. Смежный контур gost-documents (не ПНТД, но стык)

```
Organization (Норма софт | Нормасофт)
  → Document (outgoing|incoming|internal) + document_number
  → DocumentFile (docx/pdf)
  → stamp НД-XXXX-XXXX в Word (search_code / restamp)
```

Нумерация исходящих КП — **раздельная по организации** (`next_out` / max `document_number`). Метка `НД-*` — учётный код файла КП, **не** id карточки pntd.ru.

## 10. Правила нумерации и идентификации

| Контекст | Идентификатор | Формат / правило |
|----------|---------------|------------------|
| Карточка НТД | `ntd_document.id` | Целое > 0; URL `/nd/{id}.html`; стабилен |
| Обозначение НТД | `designation` | Уникально в указателе; канонический текст UI (`ГОСТ …`) |
| Классификатор | `(system, code)` | OKS / KGS / OKSTU / GRNTI; path_codes от корня к листу |
| Связь НТД | `(from_id, to_id, relation_type)` | Без петель; маркер статуса цели `Д|З|У|?` |
| SKU линейки | `(kind, code)` | `software` \| `base`; уникальность в каталоге |
| Тариф базы | `(catalog_item_id, tariff_key)` | Ключ строки, напр. `price_local` |
| Комплект | `kit_id` + строки case | months 4…100; qty 1…9999; discount при ≥12 |
| Организация (gost-documents) | `organizations.id` | 1 = ООО «Норма софт», 2 = ООО «Нормасофт» |
| Номер КП | `(organization_id, type, document_number)` | Исходящие — монотонный счётчик **внутри** org |
| Метка НД в Word | `НД-XXXX-XXXX` | 4+4 символа A–Z0–9; не пересекается с `/nd/{id}` |

Явный мост CatalogItem ↔ DocumentCard в публичном JS **не найден**; допустимая мягкая связь — опциональное поле `ntd_designation` / `ntd_document_id` в схеме линейки.

## 11. Критерии приёмки формализации (для внедрения)

Формализация считается достаточной для реализации, если выполнено:

1. **Определение:** ПНТД = «Перечень нормативно-технической документации»; две плоскости (указатель pntd.ru + линейка gost.info/pntd) и граница с gost-documents зафиксированы в этом документе и `SURFACE-MAP.md`.
2. **Сущности:** DocumentCard, ClassifierNode, NtdRelation, CatalogItem, Tariff, Kit/Case, Gate, Theme описаны атрибутами; отражены в `schema/domain.yaml` и JSON Schema.
3. **Статусы:** enum `active|replaced|cancelled|adopted|unknown` согласован с маркерами `Д|З|У|?` и CSS-классами pntd.ru.
4. **Связи:** типы `replaces|replaced_by|normative_ref_*|cited_by` и классификаторные binding’и специфицированы; DDL создаёт таблицы без секретов.
5. **Линейка:** инварианты цены/qty/скидки ≥12 мес. совпадают с публичным `/pntd/assets/app.js`.
6. **Стык с gost-documents:** таблица §6 и §9.3 / §10 явно разделяют `НД-XXXX-XXXX`, номера КП по org и id `/nd/{id}`; секреты в git не попадают.
7. **Примеры:** JSON в `examples/` валидируются против `ntd-document.schema.json` / `product-line.schema.json`.
8. **Открытые вопросы §7** помечены как out-of-scope для v0.2 (нужна сессия за gate / владелец).
